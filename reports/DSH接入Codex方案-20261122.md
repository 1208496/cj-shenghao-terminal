### 1.2 三层就绪判定脚本（PowerShell 7）

判定「现在能不能用」分三层：本地可执行与凭据存在性（纯本地）→ 登录态检查 → 医生诊断（含网络/Provider 检查）。

```powershell
# 固定绝对路径
$CODEX     = 'C:\Users\Administrator\AppData\Roaming\npm\codex.cmd'
$CODEX_DIR = 'C:\Users\Administrator\.codex'
$AUTH_FILE = Join-Path $CODEX_DIR 'auth.json'

# 1) 可执行文件与版本（纯本地）
if (-not (Test-Path -LiteralPath $CODEX)) {
    throw "BLOCKED: Codex CLI 不存在: $CODEX"
}
$verOut = & $CODEX --version 2>&1
if ($LASTEXITCODE -ne 0) {
    throw "BLOCKED: codex --version 失败 (exit=$LASTEXITCODE): $verOut"
}

# 2) auth.json 存在性与非空检查（绝不 Get-Content）
if (-not (Test-Path -LiteralPath $AUTH_FILE)) {
    throw "BLOCKED: 缺少鉴权文件 $AUTH_FILE，请用户在独立终端执行 codex login"
}
$authSize = (Get-Item -LiteralPath $AUTH_FILE).Length
if ($authSize -le 0) {
    throw "BLOCKED: 鉴权文件为空 ($AUTH_FILE)"
}

# 3) 登录态检查（带 15s 超时保护，防交互挂起）
$loginJob = Start-ThreadJob -ScriptBlock {
    param($exe)
    $out = & $exe login status 2>&1 | Out-String
    [pscustomobject]@{ ExitCode = $LASTEXITCODE; Output = $out.Trim() }
} -ArgumentList $CODEX
if (-not (Wait-Job $loginJob -Timeout 15)) {
    Stop-Job $loginJob; Remove-Job $loginJob -Force
    throw "BLOCKED: codex login status 超过 15s 未返回，疑似挂起"
}
$loginRes = Receive-Job $loginJob; Remove-Job $loginJob

# 4) 可选：运行 codex doctor --json --summary（带 30s 超时，详见 §9 报批界定）
$docJob = Start-ThreadJob -ScriptBlock {
    param($exe)
    $out = & $exe doctor --json --summary 2>&1 | Out-String
    [pscustomobject]@{ ExitCode = $LASTEXITCODE; Output = $out.Trim() }
} -ArgumentList $CODEX
if (-not (Wait-Job $docJob -Timeout 30)) {
    Stop-Job $docJob; Remove-Job $docJob -Force
    throw "BLOCKED: codex doctor 超过 30s 未返回"
}
$docRes = Receive-Job $docJob; Remove-Job $docJob

[pscustomobject]@{
    Version       = ($verOut | Out-String).Trim()
    AuthFileBytes = $authSize
    LoginExit     = $loginRes.ExitCode
    LoginStatus   = $loginRes.Output
    DoctorExit    = $docRes.ExitCode
    DoctorJson    = $docRes.Output
}
```

### 1.3 登录失效的表现与处理

- **判定信号**：
  1. `auth.json` 不存在或 0 字节；
  2. `codex login status` 非零退出，或输出含 `Not logged in` / `expired` / `unauthenticated` 等提示（**确切文案见 §12 未验证项**）；
  3. `codex doctor --json` 的 auth 检查项失败；
  4. `codex exec` 返回 `401` / `Authentication` / `refresh_token` 错误，或长时间无 JSONL 输出（类比 `agy` headless 下打印 OAuth URL 原地等待）。
- **处理动作（铁律）**：
  - 立即停止本批次所有后续 Codex 调用，不重试、不自动调用 `codex login`、不改动 `config.toml` 或 `auth.json`；
  - 向 YG 上报：`login status` / `doctor` 摘要 + 错误原文 + 日志路径，请 YG 在自己的交互终端执行 `codex login` 重新登录后再通知继续。

## 2. 最小可用调用

### 2.1 设计要点

1. **规避 Windows 命令行长度与引号问题**：`cmd.exe`（`codex.cmd` 包装层）单行上限约 8191 字符，且对双引号、`%`、`^`、`&`、`!` 极易破坏转义。因此**一律先将 prompt 写入 UTF-8 文件**，通过管道喂给 `codex exec ... -`（`-` 表示从 stdin 读取）。
2. **UTF-8 编码锁定**：在 pwsh 7 中显式设定 `$OutputEncoding = [System.Text.UTF8Encoding]::new($false)` 与 `[Console]::OutputEncoding`，避免中文 prompt / 输出经管道乱码。
3. **双路产出**：`--json` 将完整事件流重定向到 `stdout.jsonl`（供提取 `session_id` 和实时监控），`-o <FILE>` 将最终助手消息落盘（避免手写解析失误）。

### 2.2 最小可用调用模板（PowerShell 7）

```powershell
$ErrorActionPreference = 'Stop'
$utf8NoBom = [System.Text.UTF8Encoding]::new($false)
$OutputEncoding = $utf8NoBom
[Console]::InputEncoding  = $utf8NoBom
[Console]::OutputEncoding = $utf8NoBom

$CODEX      = 'C:\Users\Administrator\AppData\Roaming\npm\codex.cmd'
$WorkDir    = 'E:\SHZDCHOSSS'
$RunId      = (Get-Date -Format 'yyyyMMdd-HHmmss') + '-min'
$RunDir     = "E:\SHZDCHOSSS\.work\codex-runs\$RunId"
New-Item -ItemType Directory -Path $RunDir -Force | Out-Null

$PromptFile = Join-Path $RunDir 'prompt.txt'
$JsonlFile  = Join-Path $RunDir 'stdout.jsonl'
$StderrFile = Join-Path $RunDir 'stderr.log'
$OutFile    = Join-Path $RunDir 'last-message.md'
$Model      = ''   # 留空则沿用 config.toml 默认模型；指定时填具体模型 ID

# 写入 prompt 文件（UTF-8 无 BOM）
[System.IO.File]::WriteAllText($PromptFile, "请用一句话确认你能读取工作区，不要修改任何文件。", $utf8NoBom)

# 组装参数（注意：-a never 属于顶层 codex 选项，必须放在 exec 之前）
$argList = @(
    '-a', 'never',
    'exec',
    '-C', $WorkDir,
    '-s', 'read-only',
    '--color', 'never',
    '--json',
    '-o', $OutFile
)
if ($Model) { $argList += @('-m', $Model) }
$argList += '-'  # 从 stdin 读取 prompt

# 执行：stdout(JSONL) 与 stderr 分流落盘
$promptText = [System.IO.File]::ReadAllText($PromptFile, $utf8NoBom)
$promptText | & $CODEX @argList 1> $JsonlFile 2> $StderrFile
$exitCode = $LASTEXITCODE

# 成功 / 失败判定
$hasOut   = (Test-Path -LiteralPath $OutFile) -and ((Get-Item -LiteralPath $OutFile).Length -gt 0)
$hasJsonl = (Test-Path -LiteralPath $JsonlFile) -and ((Get-Item -LiteralPath $JsonlFile).Length -gt 0)
$isOk     = ($exitCode -eq 0) -and $hasOut -and $hasJsonl

if (-not $isOk) {
    Write-Warning "Codex 调用失败: exit=$exitCode, hasOut=$hasOut, hasJsonl=$hasJsonl, stderr=$StderrFile"
} else {
    $finalText = [System.IO.File]::ReadAllText($OutFile, $utf8NoBom)
    Write-Output "OK ($RunDir) | chars=$($finalText.Length)"
}
```

### 2.3 成功 / 失败判定标准

| 判定条件 | 要求 |
|---|---|
| 退出码 | `$LASTEXITCODE -eq 0` |
| 最终消息文件 | `$OutFile` 存在且字节数 `> 0`，非纯空白 |
| JSONL 事件流 | `$JsonlFile` 存在且至少含 1 条合法 JSON 行，且末尾无未恢复的 `error` / `turn.failed` 事件（事件名待阶段一核实） |
| 越权检查（只读模式） | 执行前后 `git status --porcelain` 无新增意外改动 |

## 4. 结构化输出与会话续接

### 4.1 从 `--json`（JSONL）提取会话 ID 与最终消息

Codex `exec --json` 向 stdout 按行输出 JSONL 事件。典型 Codex CLI 事件流首条为会话建立事件（常见字段为 `type: "thread.started"` 与 `thread_id`，部分版本或字段为 `session_id`），消息完成事件含 `agent_message` / `text`（**v0.167.1 精确 schema 列为 §12 未验证项，须在阶段一实测锁定**）。

为防止单字段名差异导致解析失败，解析脚本应采用「`-o` 文件为主 + JSONL 兼容扫描为辅」的策略：

```powershell
function Parse-CodexRun {
    param(
        [Parameter(Mandatory)][string]$JsonlFile,
        [Parameter(Mandatory)][string]$OutFile
    )
    $sessionId = $null
    $errors    = [System.Collections.Generic.List[string]]::new()
    $lastAgentText = $null
    $eventCount = 0

    if (Test-Path -LiteralPath $JsonlFile) {
        foreach ($line in [System.IO.File]::ReadLines($JsonlFile, [System.Text.UTF8Encoding]::new($false))) {
            if ([string]::IsNullOrWhiteSpace($line)) { continue }
            try {
                $ev = $line | ConvertFrom-Json -Depth 16
                $eventCount++
            } catch {
                continue
            }

            # 提取会话 ID（兼容 thread_id / session_id / thread.id）
            if (-not $sessionId) {
                if ($ev.PSObject.Properties['thread_id'] -and $ev.thread_id)       { $sessionId = [string]$ev.thread_id }
                elseif ($ev.PSObject.Properties['session_id'] -and $ev.session_id) { $sessionId = [string]$ev.session_id }
                elseif ($ev.PSObject.Properties['thread'] -and $ev.thread.id)      { $sessionId = [string]$ev.thread.id }
            }

            # 记录错误事件
            if ($ev.type -match 'error|failed') {
                $errors.Add($line)
            }

            # 兜底提取末条助手消息
            if ($ev.type -eq 'item.completed' -and $ev.item.type -eq 'agent_message' -and $ev.item.text) {
                $lastAgentText = [string]$ev.item.text
            }
        }
    }

    $finalMessage = if ((Test-Path -LiteralPath $OutFile) -and (Get-Item $OutFile).Length -gt 0) {
        [System.IO.File]::ReadAllText($OutFile, [System.Text.UTF8Encoding]::new($false))
    } else {
        $lastAgentText
    }

    [pscustomobject]@{
        SessionId    = $sessionId
        EventCount   = $eventCount
        Errors       = @($errors)
        FinalMessage = $finalMessage
    }
}
```

第一轮成功后，DSH 将会话元数据写入项目内状态文件（如 `E:\SHZDCHOSSS\.work\codex-runs\session-latest.json` 或任务专属 `session-<任务短名>.json`）：

```json
{
  "session_id": "<从 JSONL 提取的 UUID>",
  "model": "<所用模型>",
  "sandbox": "read-only",
  "cwd": "E:\\SHZDCHOSSS",
  "created_at": "2026-11-22T20:45:00+08:00",
  "last_run_dir": "E:\\SHZDCHOSSS\\.work\\codex-runs\\20261122-204500-review"
}
```

### 4.2 精确续接（`exec resume`）

根据本机 `codex exec resume --help` 实测语法：`codex exec resume [OPTIONS] [SESSION_ID] [PROMPT]`，`PROMPT` 传 `-` 时同样从 stdin 读。

### 4.3 为什么严禁使用 `--last`

与 `agy` 禁用 `-c` / `--continue` 完全同构：
1. **并行污染**：DSH 主代理、子代理、或 YG 本人在其他窗口运行任何 Codex 交互会话，都会立刻改写「最近一次会话」指针，`--last` 会把续接消息打进毫不相干的会话。
2. **探针干扰**：一旦忘了加 `--ephemeral`，一次探针就会成为最新会话，后续 `--last` 会续接到探针里。
3. **不可审计**：留痕中无法仅靠命令行反查究竟续接了哪条线程。

**硬规则**：所有续接必须显式传入 `<SESSION_ID>`；若第一轮未拿到 `session_id`，视为提取失败，停手排查 `stdout.jsonl` 与 `session_index.jsonl`，禁止用 `--last` 凑合。

## 5. 超时与卡死处置

### 5.1 Windows 进程树真相与整树清理

经本机核查 `C:\Users\Administrator\AppData\Roaming\npm\codex.cmd` 与 `codex.js`，Windows 下调用 `codex.cmd` 会形成多层进程树：

```text
pwsh.exe (DSH 后台作业)
  └─ cmd.exe (codex.cmd)
       └─ node.exe (node_modules\@openai\codex\bin\codex.js)
            └─ codex.exe (原生 Rust 二进制)
                 └─ [工具调用子进程，如 pwsh.exe / cmd.exe]
```

**关键陷阱**：`Stop-Process -Id <wrapperPid> -Force` 只杀最上层的 `cmd.exe`（或 `node.exe`），底层的 `codex.exe` 会变成孤儿进程继续在后台跑并持续消耗额度！

**唯一合法的整树终止方式**（仅限探针超时自动触发，或 YG 文字明确授权后对正式任务执行）：

```powershell
# 方式 A（推荐，Windows 通用，强制结束指定 PID 及其全部子进程）
& taskkill.exe /PID $WrapperPid /T /F

# 方式 B（.NET / PowerShell 7 原生，同样支持整树终止）
# [System.Diagnostics.Process]::GetProcessById($WrapperPid).Kill($true)
```

### 5.2 pwsh 侧进程启动、PID 记录与超时看门狗

正式任务一律通过 DSH `pwsh`（`run_in_background`）启动，启动脚本先把进程 PID 与路径写入 `run.meta.json`，再由外部循环监控：

```powershell
# E:\SHZDCHOSSS\scripts\dsh-codex\start-codex-bg.ps1（示意落点）
param(
    [Parameter(Mandatory)][string]$RunDir,
    [Parameter(Mandatory)][string]$PromptFile,
    [string]$WorkDir = 'E:\SHZDCHOSSS',
    [ValidateSet('read-only','workspace-write','danger-full-access')]
    [string]$Sandbox = 'read-only',
    [string]$Model = '',
    [string]$SessionId = '',
    [switch]$Ephemeral,
    [int]$TimeoutSec = 900,
    [switch]$AutoKillOnTimeout  # 仅探针传 $true；正式任务严禁传 $true！
)

$ErrorActionPreference = 'Stop'
$CODEX      = 'C:\Users\Administrator\AppData\Roaming\npm\codex.cmd'
$JsonlFile  = Join-Path $RunDir 'stdout.jsonl'
$StderrFile = Join-Path $RunDir 'stderr.log'
$OutFile    = Join-Path $RunDir 'last-message.md'
$MetaFile   = Join-Path $RunDir 'run.meta.json'

# 构造传给 cmd.exe /c 的安全调用：stdin 从 PromptFile 重定向，彻底避开引号转义
$cmdArgs = @('-a', 'never', 'exec')
if ($SessionId) {
    $cmdArgs += @('resume', '--json', '-o', $OutFile)
    if ($Model) { $cmdArgs += @('-m', $Model) }
    if ($Ephemeral) { $cmdArgs += '--ephemeral' }
    $cmdArgs += @($SessionId, '-')
} else {
    $cmdArgs += @('-C', $WorkDir, '-s', $Sandbox, '--color', 'never', '--json', '-o', $OutFile)
    if ($Model) { $cmdArgs += @('-m', $Model) }
    if ($Ephemeral) { $cmdArgs += '--ephemeral' }
    $cmdArgs += '-'
}

$psi = [System.Diagnostics.ProcessStartInfo]::new()
$psi.FileName               = 'cmd.exe'
$psi.Arguments              = '/d /s /c ""' + $CODEX + '" ' + (($cmdArgs | ForEach-Object { if ($_ -match '\s') { "`"$_`"" } else { $_ } }) -join ' ') + '"'
$psi.WorkingDirectory       = $WorkDir
$psi.UseShellExecute        = $false
$psi.RedirectStandardInput  = $true
$psi.RedirectStandardOutput = $true
$psi.RedirectStandardError  = $true
$psi.StandardOutputEncoding = [System.Text.UTF8Encoding]::new($false)
$psi.StandardErrorEncoding  = [System.Text.UTF8Encoding]::new($false)

$proc = [System.Diagnostics.Process]::Start($psi)

# 记录元数据供三路监控与审计
$meta = @{
    wrapper_pid  = $proc.Id
    started_at   = (Get-Date -Format 'o')
    timeout_sec  = $TimeoutSec
    auto_kill    = [bool]$AutoKillOnTimeout
    sandbox      = $Sandbox
    model        = $Model
    session_id   = $SessionId
    jsonl_file   = $JsonlFile
    stderr_file  = $StderrFile
    out_file     = $OutFile
}
$meta | ConvertTo-Json | Set-Content -LiteralPath $MetaFile -Encoding utf8NoBOM

# 异步写 stdout / stderr 到文件，并一次性喂入 prompt 后关闭 stdin
$stdoutTask = $proc.StandardOutput.ReadToEndAsync()
$stderrTask = $proc.StandardError.ReadToEndAsync()
$promptText = [System.IO.File]::ReadAllText($PromptFile, [System.Text.UTF8Encoding]::new($false))
$proc.StandardInput.Write($promptText)
$proc.StandardInput.Close()

# 轮询等待（非死等，便于看门狗触发）
$sw = [System.Diagnostics.Stopwatch]::StartNew()
while (-not $proc.HasExited) {
    Start-Sleep -Seconds 2
    if ($sw.Elapsed.TotalSeconds -ge $TimeoutSec) {
        if ($AutoKillOnTimeout) {
            & taskkill.exe /PID $proc.Id /T /F | Out-Null
            [pscustomobject]@{ Status = 'TIMEOUT_KILLED'; ElapsedSec = [int]$sw.Elapsed.TotalSeconds; WrapperPid = $proc.Id } | ConvertTo-Json
            exit 124
        } else {
            # 正式任务超过 900s：写超时标记但不自行杀进程，交由主代理按卡死流程取证并报 YG
            [pscustomobject]@{ Status = 'TIMEOUT_WAITING_USER'; ElapsedSec = [int]$sw.Elapsed.TotalSeconds; WrapperPid = $proc.Id } | ConvertTo-Json
            exit 125
        }
    }
}

[System.IO.File]::WriteAllText($JsonlFile,  $stdoutTask.GetAwaiter().GetResult(), [System.Text.UTF8Encoding]::new($false))
[System.IO.File]::WriteAllText($StderrFile, $stderrTask.GetAwaiter().GetResult(), [System.Text.UTF8Encoding]::new($false))

[pscustomobject]@{
    Status     = if ($proc.ExitCode -eq 0) { 'EXITED_OK' } else { 'EXITED_ERR' }
    ExitCode   = $proc.ExitCode
    ElapsedSec = [int]$sw.Elapsed.TotalSeconds
    WrapperPid = $proc.Id
} | ConvertTo-Json
```

> **重要实现注记**：上面用 `ReadToEndAsync()` 会把 stdout 缓存在内存直到进程退出，**正式长任务**需要流式落盘以便三路监控实时 tail。实际落地 `start-codex-bg.ps1` 时，正式任务应改用 `cmd.exe` 文件重定向 `1>"$JsonlFile" 2>"$StderrFile" <"$PromptFile"`（这样每一行 JSONL 产生时即刻可见），仅将 `ProcessStartInfo` 设为不重定向流。示例如下：
> ```powershell
> $psi.Arguments = "/d /s /c `"`"$CODEX`" $joinedArgs < `"$PromptFile`" 1>`"$JsonlFile`" 2>`"$StderrFile`"`""
> $psi.RedirectStandardInput  = $false
> $psi.RedirectStandardOutput = $false
> $psi.RedirectStandardError  = $false
> ```

### 5.3 三路监控与疑似卡死判定（照抄 agy §4）

- **监控频率**：每 ≤2 分钟巡检一次，禁止用单次 900s 长等待睡过去。
- **三路信号**：
  1. `job_output`（DSH 后台作业输出）；
  2. `stdout.jsonl`、`stderr.log` 以及 `C:\Users\Administrator\.codex\sessions\YYYY\MM\DD\rollout-*.jsonl` 最新文件的末行与 `LastWriteTime`；
  3. 进程树 CPU 增量：`Get-Process -Name codex,node -ErrorAction SilentlyContinue | Select-Object Name,Id,CPU,StartTime`（隔 5 秒采两次）。
- **疑似卡死定义**：运行超过 **10 分钟**，且 `stdout.jsonl` 与最新 `rollout-*.jsonl` 均无新行。
- **只读取证顺序（取证前严禁改变进程状态）**：
  1. `Get-Content $JsonlFile -Tail 30`、`Get-Content $StderrFile -Tail 30`、最新 `rollout-*.jsonl` 末 20 行；
  2. 两次采样 `Get-Process -Name codex -ErrorAction SilentlyContinue | Select-Object Id,CPU,StartTime`（看 CPU 是否增长）；
  3. 读取 `job_output` 已产出内容。
- **一次上报六项**：① 进程树是否存活（`wrapper_pid` 与 `codex.exe` PID）；② CPU 是否增长；③ `stdout.jsonl` / `stderr.log` / `rollout` 最后一行原文；④ 已卡时长；⑤ 判断与证据；⑥ 建议。
- **处置权归 YG**：正式任务严禁 DSH 自行 `taskkill` / `Stop-Process` / `job_kill`，严禁未查明原因就重跑或换模型；只有 YG 文字说出「杀掉 / 停掉 / 重开 / 别等了」后，才执行 `taskkill.exe /PID <wrapper_pid> /T /F`。

## 6. 探针

### 6.1 探针策略（同构 agy §3）

- **目的**：只回答「该模型通道现在能不能通、会不会卡死」，绝不夹带正式任务内容。
- **间隔**：同一模型距上次**通过**的探针不足 **2 小时** 则免探；满 2 小时或从未探过，正式调用前必探；YG 明说「探一下」时即探。探针时间戳记入 `E:\SHZDCHOSSS\.work\codex-runs\probe-history.jsonl`。
- **最省额度参数组合**：
  - `-a never`（无交互审批）
  - `-s read-only`（只读沙箱）
  - `--ephemeral`（不写 `sessions/` 历史文件）
  - `--skip-git-repo-check`（不依赖 git 目录）
  - `--color never`
  - prompt 固定为：`只回复一个字：好`

### 6.2 60 秒硬闸探针脚本（PowerShell 7）

```powershell
param(
    [string]$Model = '',
    [int]$TimeoutSec = 60
)

$ErrorActionPreference = 'Stop'
$CODEX     = 'C:\Users\Administrator\AppData\Roaming\npm\codex.cmd'
$RunDir    = "E:\SHZDCHOSSS\.work\codex-runs\probe-$(Get-Date -Format 'yyyyMMdd-HHmmss')"
New-Item -ItemType Directory -Path $RunDir -Force | Out-Null

$PromptFile = Join-Path $RunDir 'prompt.txt'
$JsonlFile  = Join-Path $RunDir 'stdout.jsonl'
$StderrFile = Join-Path $RunDir 'stderr.log'
$OutFile    = Join-Path $RunDir 'last-message.md'

$utf8NoBom = [System.Text.UTF8Encoding]::new($false)
[System.IO.File]::WriteAllText($PromptFile, '只回复一个字：好', $utf8NoBom)

$modelArg = if ($Model) { "-m `"$Model`"" } else { '' }
$cmdLine  = "/d /s /c `"`"$CODEX`" -a never exec -s read-only --ephemeral --skip-git-repo-check --color never $modelArg --json -o `"$OutFile`" - < `"$PromptFile`" 1>`"$JsonlFile`" 2>`"$StderrFile`"`""

$psi = [System.Diagnostics.ProcessStartInfo]::new('cmd.exe', $cmdLine)
$psi.WorkingDirectory = 'E:\SHZDCHOSSS'
$psi.UseShellExecute  = $false

$sw   = [System.Diagnostics.Stopwatch]::StartNew()
$proc = [System.Diagnostics.Process]::Start($psi)

$killed = $false
while (-not $proc.HasExited) {
    Start-Sleep -Milliseconds 500
    if ($sw.Elapsed.TotalSeconds -ge $TimeoutSec) {
        & taskkill.exe /PID $proc.Id /T /F | Out-Null
        $killed = $true
        break
    }
}
$sw.Stop()

$reply = if ((Test-Path -LiteralPath $OutFile) -and (Get-Item $OutFile).Length -gt 0) {
    ([System.IO.File]::ReadAllText($OutFile, $utf8NoBom)).Trim()
} else { '' }

$passed = (-not $killed) -and ($proc.ExitCode -eq 0) -and ($reply.Length -gt 0)

# 追加记录到本地探针台账
$record = [pscustomobject]@{
    timestamp   = (Get-Date -Format 'o')
    model       = if ($Model) { $Model } else { '(default)' }
    passed      = $passed
    killed      = $killed
    exit_code   = if ($killed) { 124 } else { $proc.ExitCode }
    elapsed_sec = [math]::Round($sw.Elapsed.TotalSeconds, 1)
    wrapper_pid = $proc.Id
    reply       = $reply
    run_dir     = $RunDir
}
$record | ConvertTo-Json -Compress | Add-Content -LiteralPath 'E:\SHZDCHOSSS\.work\codex-runs\probe-history.jsonl' -Encoding utf8NoBOM
$record | Format-List
```

> **60 秒硬闸权限**：与 agy §3.4 同构，**探针超时自动 `taskkill /PID $proc.Id /T /F`** 是执行代理唯一可以自行结束 Codex 进程的情形，且**只适用于探针进程**。

### 6.3 探针失败的五项上报内容

探针超时被杀、非零退出或没有回字 → **本批次立即终止**（不换模型、不改 prompt 重发、不自动切 agy），一次报齐五项：
1. **等了多久**（秒数）
2. **有没有回字**（`$OutFile` 与 `$JsonlFile` 末行摘录）
3. **已终止的 PID**（`wrapper_pid`，并确认 `Get-Process codex` 无残留）
4. **日志路径**（`$JsonlFile`、`$StderrFile`、`$RunDir`）
5. **我的建议**（例如：先跑 `codex login status` / `codex doctor --json`，或等待限流窗口恢复）

## 7. 权限档位与防误用设计

### 7.1 三档权限映射

| 档位 | 适用场景 | Codex CLI 参数表达 | 风险等级 |
|---|---|---|---|
| **档位 1：只读审查（默认）** | 代码审查、架构诊断、方案撰写（产出由 `-o` 落盘，不让模型改工作区文件） | `codex -a never exec -C <DIR> -s read-only ...` | 低 |
| **档位 2：工作区写** | 允许 Codex 直接在工作区内写方案 `.md` 或改代码 | `codex -a never exec -C <DIR> -s workspace-write [--add-dir <EXTRA>] ...` | 中 |
| **档位 3：全放开（禁区）** | 仅当 Windows 原生沙箱失效且任务必须执行不受限命令，并经 YG 逐次特批 | `codex exec -C <DIR> --dangerously-bypass-approvals-and-sandbox ...` | **极高** |

### 7.2 DSH 侧防误用机制

1. **封装脚本默认锁定 `read-only`**：不传 `-Mode` 时强制 `-s read-only`，调用方不可能因漏参而意外放开写权限。
2. **申请单显式声明档位**：申请单第 2 项必须写明「权限档位：只读审查 / 工作区写 / 全放开」；若为「工作区写」，须列明目标写入路径；若为「全放开」，须单列一行写明为何前两档不可用。
3. **双开关拦截档位 3**：封装脚本要求同时传入 `-Mode DangerFullAccess -ConfirmBypassSandbox` 才拼装 `--dangerously-bypass-approvals-and-sandbox`，且禁止出现在任何默认示例或 skill 快捷模板中。
4. **只读档位后置校验**：档位 1 执行完后，自动对比 `git status --porcelain`，若出现未预期文件变更立即告警。

### 7.3 Windows 沙箱降级预案（待阶段一实测）

`agy` 曾在本机遇到 `Terminal sandbox unavailable`（受 Windows 11 24H2 更新要求影响）。若阶段一实测发现 Codex 的 `-s read-only` / `-s workspace-write` 在本机同样因 Windows 沙箱受限而无法执行，**不得静默升级到 `--dangerously-bypass-approvals-and-sandbox`**，应立即停手上报 YG，由 YG 决定是改用纯 stdin 喂文件（不让 Codex 调壳命令）还是按单次特批放开。

## 12. 风险与未验证项

### 12.1 本机尚未实测验证的项（须在阶段 0 / 阶段 2 逐项核实）

1. **`codex exec --json` 在 v0.167.1 的确切 JSONL schema**：会话 ID 字段名究竟是 `thread_id`、`session_id` 还是嵌套字段；错误/完成事件的 `type` 精确取值。
2. **`codex exec resume` 的参数继承与覆盖**：`codex exec resume --help` 未列出 `-s/--sandbox` 与 `-C/--cd`，需实测顶层 `codex -a never -s read-only exec resume <ID> -` 是否生效，或是否必须用 `-c sandbox_mode="read-only"`。
3. **Windows 环境下 Codex 原生沙箱可用性**：`-s read-only` 与 `-s workspace-write` 在当前 Windows 系统上是否正常运行，还是会像 `agy` 一样出现 Windows 沙箱不可用错误。
4. **登录失效时的真实退出行为**：`auth.json` 过期或撤销时，`codex exec` 与 `codex login status` 是立即非零退出，还是会挂起等待浏览器授权（决定 60s 探针硬闸是否会高频触发）。
5. **`codex doctor --json` 的实际结构与耗时**：在代理/网络波动时的响应时间、退出码含义，以及是否会触发任何写入或锁冲突。
6. **可用模型 ID 清单**：Codex CLI 没有 `codex models` 子命令（`codex -h` 中无此项），当前账户实际可用模型 ID 需核查 `C:\Users\Administrator\.codex\models_cache.json` 或在阶段 2 实测确认。
7. **`logs_2.sqlite` 的表结构与写入时机**：是否实时刷盘、WAL 模式下直接复制是否完整、能否像 `agy` 的 `cli-*.log` 一样作为卡死排查的补充证据源。
8. **DSH 后台 `pwsh` 环境变量**：`codex.cmd` 依赖 `node` 在 `PATH` 中（或位于 `%dp0%\node.exe`）；需确认 DSH 启动快照的 `PATH` 下能否找到 `node.exe`，否则需在封装脚本里显式把 `node.exe` 所在目录拼进子进程 `PATH`。

### 12.2 主要运行风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| `Stop-Process` 只杀 `cmd.exe` 导致 `codex.exe` 孤儿进程继续烧额度 | 额度暗中消耗、锁住文件 | 全链路禁用单 PID `Stop-Process`，强制 `taskkill.exe /PID <wrapper_pid> /T /F` |
| `codex.cmd` 经 `cmd.exe` 传参时特殊字符/超长 prompt 被截断或注入 | 提示词损坏或报错 | 强制「UTF-8 文件 + stdin 重定向 `< prompt.txt`」，绝不把 prompt 拼进命令行参数 |
| `ReadToEndAsync()` 缓冲导致长任务期间 `stdout.jsonl` 为空 | 三路监控失明、误判卡死 | 正式任务一律采用 `1>"stdout.jsonl" 2>"stderr.log"` 直接文件重定向，保证实时落盘 |
| 缺少命令行 `/usage` 导致不知不觉触发限流 | 批次中途失败 | 每次任务控制读取范围与单轮体量；记录 `probe-history.jsonl` 与每次耗时；遇限流立即停手上报 |
| 未验证的 Windows 沙箱失败被静默绕过 | 越权修改工作区外文件 | 封装脚本严禁自动降级到 `--dangerously-bypass-approvals-and-sandbox`，遇到沙箱错误硬停上报 |
