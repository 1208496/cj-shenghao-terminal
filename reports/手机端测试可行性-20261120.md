# 手机端（移动环境）测试可行性 · 2026-11-20

> 结论先说：**能**。ego 的 Chromium 可以通过 CDP 原生设备仿真把页面切成手机环境（已实测通过），
> 但只能仿 Android Chrome 一档；**iOS Safari 的真机差异测不出来**，那一块只能真机验。
> 本文只记录能力与边界，没有改任何卡或配置。

## 一、实测证据（本轮探针）

脚本：`.work/mobile-probe/probe-01.mjs`（space `MOBILE-EMU-PROBE`，跑完已 `finish`）。

```
Emulation.setDeviceMetricsOverride  → ok   (390×844, dpr 3, mobile:true)
Emulation.setTouchEmulationEnabled  → ok   (maxTouchPoints 5)
Emulation.setUserAgentOverride      → ok   (Pixel 7 / Android 13 / Chrome 131 Mobile)
页面内实测: innerHeight 844 · devicePixelRatio 3.0
            maxTouchPoints 5 · (pointer: coarse) true · (hover: none) true
            screen 390×844 · UA 已是 Android Chrome
```

`(pointer: coarse)` 与 `(hover: none)` 都为 true，说明**卡里的移动端媒体查询、hover 降级分支会真的进**，
不是把窗口拉窄糊弄出来的假移动端。

## 二、和现在 457×926 那套的区别

现有 `scripts/noapi/*` 里**没有任何 `Emulation.*` 调用**（已 grep 确认），所以过去的"窄屏"只是把视口缩窄：

| | 现有 457×926 | CDP 设备仿真 |
|---|---|---|
| CSS 宽度 | 窄 | 窄 |
| `hover: none` / `pointer: coarse` | 仍是桌面 | **真移动端** |
| DPR | 1 | 3（1px 边线、字体渲染、截图像素都变） |
| 触屏事件链 | 合成 pointerup 靠脚本补 | 真 touch 链路 |
| UA / `100dvh` / `visualViewport` | 不变 | 跟随仿真 |

这也是 rc.37 那个"折叠球在手机不展开"的 bug 的成因：合成了 `click` 没合成 `pointerup`。
放到真移动环境里，这类问题会自己冒出来。

## 三、手机端"交合渲染"该验什么（可测清单）

1. **长段露骨正文的窄屏排版**：390px 下每行字数、行高、段间距、有没有横向溢出/撑破气泡。
2. **一屏信息量**：一段交合描写在手机上一屏能看到几句，滚动长度是否失控。
3. **状态栏 / 小手机**：情欲值、生理状态、处子状态、`她们`页私密字段（性器规格、床笫战力）在窄屏的换行与截断。
4. **底部停靠**：正文底部栏 + 小手机重叠、`100vh` vs `100dvh`（地址栏收放）导致的错位。
5. **触屏交互**：折叠球/悬浮球展开、拖动、长按，是否真的靠 pointer 链而不是 click 兜底。
6. **软键盘**：背包"塞输入框"、开场表单聚焦时 `fixed` 元素被顶飞、iOS 输入框 <16px 自动放大页面。
7. **DPR 3 观感**：哥特符号、金光落点、1px 描边在 3 倍屏是否发虚或过粗。
8. **性能**：244 节点 SVG + 特效在手机 GPU 上的 longtask；`PageUnresponsive` 是否更早出现。
9. **成人内容开关**：ST 的敏感内容/正则渲染在移动端是否一致（同引擎，预期一致，但要留一条断言）。

## 四、测不了的部分（必须说清）

- **iOS Safari**：ego 是 Chromium，`-webkit-backdrop-filter`、Safari 的 `dvh` 实现、橡皮筋滚动、
  输入框自动缩放、Safari 的字体回退，全都测不到。
- **真机 GPU / 真机内存**：仿真仍是 PC 的渲染管线，手机性能只能靠真机。
- **真机字体**：安卓/iOS 的中文字体回退不同，窄屏换行位置会差几个字。

## 五、真机的唯一路径（要用时）

8001 现在没在监听（本轮 `Get-NetTCPConnection -LocalPort 8001` 无结果）。
真机测法：ST 开 `listen`（config 里 `listen: true` 或用启动参数）+ 手机同一局域网访问 `http://<PC 局域网IP>:8001`，
再确认 `whitelistMode` 放行该 IP。iOS 用 Safari 的 Web Inspector、安卓用 `chrome://inspect` 挂上去看 console。
这条要动 ST 的全局配置，做之前我会先报你。

## 六、建议的分层

| 层 | 手段 | 成本 | 覆盖 |
|---|---|---|---|
| L1 回归 | ego CDP 仿真 + 现有零 API 套件（加一个 mobile profile） | 0 元、可断言 | 布局/媒体查询/触屏/DPR |
| L2 真机 | 安卓真机局域网直连 8001 | 手工、几十分钟 | 真触屏/真 GPU/真字体 |
| L3 iOS | 只能真机 | 手工 | Safari 专项 |
