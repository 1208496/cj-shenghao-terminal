## 一、结论先说：GO 卡点的真因不是 UI，是预置存档自己不合账

| 说法 | 判定 | 证据 |
|---|---|---|
| 假设①：进聊天时 `view.busy` 未落定 → GO 是 disabled | **不成立** | `#wfGo` 实测 `disabled:false`、`aria-disabled:false`、`visible:true`、`coveredBy:null`、`busyReasons` 四位全 false |
| 假设②：`expectedRevision` 与宿主不一致 → `STALE_REVISION` | **不成立** | 旁听到 `WHEEL_OP_REQ` 带 nonce `dbb41950`，与宿主 `wheelNonce` 完全一致；`api.action` 被真实调用 1 次 |
| **真实原因** | **`LEDGER_MISMATCH`** | 给 `api.action` 装监视后：调用 1 次、成功 0 次、异常 `["LEDGER_MISMATCH"]` |

根因链条：

1. `mutateState`（host.js:226）→ `replayPlayerCommand` → `assertState` → `assertEconomy`（engine.js:1063）；
2. 该断言要求 `cashCents === initialCashCents + (账本收入 − 账本支出)`；
3. 预置脚本 `three_cards` 把 `cashCents` 从 20 万改成 150 万，但没改 `initialCashCents`（仍是 20 万），账本为空 → 差额 130 万 → 直接抛 `LEDGER_MISMATCH`；
4. 宿主把 `WHEEL_OP_RES{ok:false}` 回给轮盘，轮盘解除 busy、不落结果 → 旧脚本看到的就是 `spinning:false / rev 不变 / result 空`，最后报成一个笼统的 `WHEEL_SETTLE_TIMEOUT`。

**5 套预置里 4 套（three_cards / wish_unlocked / high_wealth / max_pity）都是这种账目不一致**，也就是说：直到这轮为止，任何"要改状态"的交互在这些预置上都不可能成功。之前记录的「5 套预置全 PASS」只证明了渲染，不证明功能。
