## 2. 三个此前未验证、现在有答案的问题

1. **`Page.captureScreenshot` 在 ego 里通不通** → 通，返回形状是 `{data}`，和 Playwright 的 CDP 直连一致。
2. **CDP 通道有没有 `clip` 的那个 1.25 倍怪相** → **没有**。CDP 输出直接按 `dpr = 1.5625` 栅格化（`rasterK = 1.5629`）。所以之前实测的 `1.25` 是 **`page.screenshot({clip})` 这条通道自己的行为**，不是浏览器的栅格系数。这也是「上一轮按 1.25 换算永远偏」的真正来源。
3. **角标挂进目标内部会不会改布局** → 不会（`position:absolute` 四角小方块，`clientWidth/Height` 不变）。

## 3. 对真实场景（工坊截图）的直接推论

- 顶层元素**没有被任何宿主缩放**：`sx/sy` 与视口栅格系数完全一致。这与前提修正一致——之前那个「0.34×」确实是视口裁切造成的假象。
- 因此搬进 iframe 后要回答的只剩：**iframe 内的元素相对视口有没有额外缩放**。仿射拟合会直接给出 `sx/sy`，不再靠肉眼和试错。
- 通道选择确定：**CDP 为主**（`page.cdp('Page.captureScreenshot')`），`page.screenshot({clip})` 不再用于精确裁切。

## 4. 过程中的两处自我修正（留痕）

1. 第一版 `verify.mjs` 的 `notFlat` 检查把采样点定在 CSS `(150,100)`，落在纯背景上，导致误报 `FAIL_CHECKS`。改为「文字带内亮像素计数 > 80」后转绿。教训：**判据本身要有判别力，不能用一个可能落在空白处的点冒充内容证明。**
