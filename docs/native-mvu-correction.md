# 原生 MVU 修正计划

本轮以用户 2026-11-16 的验收反馈为准。此前测试证明过部分算账和受控消息回放，不能证明自然游玩、真实 MVU、拖动与完整视觉已经通过；旧版通过结论不继承到本次重做。

## 纠正后的交付契约

1. 主类型 `mvu_zod`。随卡携带变量结构、国内/国际两个原生 MVU 加载器（仅启用一个）、手机及确定性结算脚本。
2. 使用 MagVarUpdate 真正的 `[InitVar]` 初始化、`<UpdateVariable><JSONPatch>` 输出、原生消息楼层保存及官方额外模型解析；取消手机自建“整理”请求和自定义 SH_EVENTS 主协议。
3. `stat_data.shenghao` 是唯一世界状态。模型直接更新当前场景、人物动态、世界时间、天气和日历。财务/产权/行为评分候选由 MVU 接收，脚本在 MVU 生命周期内校验、计算，模型不可直接改现金或奖池。
4. Zod 的来源是已探测酒馆助手提供的 Zod 4；注册器按已阅读的 StageDog 上游源码锁定提交。原生 MVU 按已阅读上游源码锁定提交。两者来源及版权通知明确记录。
5. 开局页仍在首条正文。提交真实玩家消息，使用原生 MESSAGE_SENT → MVU 更新链初始化；不伪造初始化事件，不先写一份独立手机存档。
6. 拖动由顶层同一坐标系处理。展开手机与折叠入口共用规则；连续移动必须跟随鼠标，不仅检查最终坐标变化。
7. 视觉沿用 SHEJI 原型的完整卡片结构、色值、层级、字号与紧凑度。精巧模式缩放整体比例；时间、日历、更新详情和错误弹窗采用同套组件。所有弹窗有可见关闭按钮和 Escape。
8. 新增日历与游戏时间是本轮用户明确变更。保留三个主入口；日历从「此刻」的日期区域进入。时间随剧情变量推进，不伪装成电脑实时时钟。
9. 从旧项目参考世界观、都市社会逻辑、财富与声望独立、时间和约定连续性、可拖动入口。保留 v2 已确认奖池规则；不带回 E–S 等级、自动派奖、P站或私信。

## 验收顺序

真实 Mvu 全局及 Zod 注册 → 新聊天 InitVar → 正常开局 → 自然生成原生变量 → 原生额外模型解析 → 场景与人物持续同步 → 时间和日历 → 真实鼠标拖动轨迹 → 三主题及全部弹窗 → 消费/暴击/提现/回退 → GitHub 更新及关闭。

自然模型回合、手工控制场景、离线单元测试分别记录，不用后两者替代自然游玩验收。失败项不写成通过。
