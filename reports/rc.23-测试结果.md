## 三、rc.22 → rc.23 的关键差异

1. **脚本兜底确实解决了「模型漏写」**：rc.22 里 virgin / tags 靠模型写、失败即空白；rc.23 即使模型完全不写这两项，`BEHAVIOR.score >= 90` 也会触发 `virgin=false` + 标签提炼。
2. **模型换掉后 `offscreen` 写对了**：rc.22 那轮模型把 `offscreen` 写成人物不存在的旧 ID，更新落空；这次新模型的 ID 与状态一致，`starredOffscreenIds` 的顶层提醒也起了作用。
3. **仍存在的模型风险**：rc.22 曾出现模型写错人物 ID 导致整段 JSONPatch 落空。这不是卡的缺陷，但说明「脚本兜底」必须有——它兜住了 `virgin` 和标签，兜不住 `traits`（那是纯文本，只能靠模型）。

## 四、环境层注意事项（复测必看）

1. **刷新页面后 API 会自动断连**，必须重新点「API状态」→「连接」，等插头从 `fa-plug-circle-exclamation` 变成 `fa-plug` 再继续。
2. **酒馆助手的脚本注入需要一个完整的「打开角色 → 切换 → 回来」周期**才会提供 `z`（Zod）与 `Mvu`。导入后立刻点开角色，会出现「Zod 注册失败 + 加载器报未下载」的假故障；切一次角色再回来即恢复。
3. **jsDelivr 对新提交的缓存有延迟**：指针刚切换的几分钟内，加载器首次拉取可能 404 并弹「脚本没有下载或启动成功」，此时调用一次 `__CJ_SHENGHAO_SCRIPT_LOADER__.reload()` 或重进角色即可。
4. 以上三条都与卡本身无关；网络实测三个 CDN 节点、MVU 包、StageDog 注册器全部 200。

## 五、补充测试（同日，同一聊天继续）

### 5.1 多个打星离场人物同时更新 `offscreen`

给温迎、沈清弦、林知夏三人全部打星，`_context.starredOffscreenIds` 返回三条 ID（与人物一一对应）。发一轮同时提到三人的正文后，**三人全部写出各自的 offscreen**：

| 人物 | offscreen |
| --- | --- |
| 温迎 | 花艺工作室内 · 刚发完朋友圈，正忙着修剪新到的浅粉荔枝玫瑰 |
| 沈清弦 | 书房电脑前 · 整理今晚要通宵赶制的稿件资料，刚给测试员发完消息 |
| 林知夏 | 办公室内 · 已发送修改后的合同附件与报价单，等待对方核对 |

结论：顶层待办列表对多人场景有效，不需要模型自己记住谁打了星。

### 5.2 只靠堕落度解锁提现（方案 B1 第二通道）

把苏晚的好感压低、堕落推高，最终停在 **♥62 / ❖70**（好感 < 70，堕落 ≥ 60）：

| 检查项 | 结果 |
| --- | --- |
| 提现按钮 | 由「♥ 好感达70 或 ❖ 堕落达60 解锁提现」变为 **「✦ 领取本期全部奖励」，disabled = false** |
| 确认弹窗 | 「苏晚 · 本期原始奖池 ¥685,000 / 见习·十倍 · 理论到账 ¥6,850,000 / 本次实到 ¥6,850,000」 |
| 提现后现金 | 8,000,000 分 → **693,000,000 分**（+685,000,000，与 gross 完全一致） |
| 提现记录 | `withdrawals` 新增 1 条，`basePoolCents=68,500,000`、`multiplier=10`、`paid=685,000,000` |
| 账本 | `WITHDRAWAL_REWARD` 收入合计 685,000,000，与到账一致 |

结论：堕落通道能独立解锁提现，且底层账本、倍率、退款追回公式未被改写。

### 5.3 过程中观察到的模型行为

- `corruption` 上升由模型决定，且**单轮封顶 ±12**：实测 12 → 20 → 26 → 34 →（两轮停住）→ 46 → 58 → 70。
- 剧情没推进时，模型会连续几轮不写 `corruption`（不给新越界就不加分），这符合设计，不是卡顿。
- 好感在被冷处理/金钱化的剧情里会**下降**（48 → 45 → 43 → 39），与堕落形成反向走势，「低好感高堕落」象限可稳定构造出来。
