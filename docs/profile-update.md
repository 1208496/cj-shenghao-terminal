# rc.7 人物档案与手机调整

2026-11-16；以本轮用户批准的完整方案及后续补充为准，覆盖总纲中自动完整建档等旧描述。

## 有效规则

- 玩家开局填写年龄、外貌、身材，“我的”顶部展示同一份资料。
- 女性正式相识或作为初始熟人时只生成简易资料：年龄、职业、外貌、身材、性格标签（1–6个）、身高CM、体重KG、三围CM、鞋码欧码。已填写值优先，身体数值和标签保存后保持稳定。
- 简易阶段启用基础奖池10000元；完整建档和锁定不改变经济。
- 九大档案默认空，只有玩家确认建档才生成，九类校验完整后一次保存。依据基础信息、玩家备注、已确认经历；失败可重试，不推进剧情。生成期间切聊天或分支改变拒绝旧结果。
- 档案默认未锁定；在场且未锁定才发送九类。锁定后停止主动发送九类，手机仍能查看。离场和隐藏者只有ID、姓名、别名、隐藏标记。历史聊天内容不随锁定删除。
- 公共资料条目同时提供给剧情和原生变量更新模型，更新规则单独保留。禁止普通回复自动补全九类或改变锁定。
- 神情放在现场展开区，姿态和动作分别显示；补充心情、身体状态、随身物品。没有依据显示尚未记录。
- 隐藏正式/临时人物必须确认，取消不写状态；恢复不传送、不重复发基础金。
- 设置字号小/中/大对应1/1.15/1.3倍；精巧默认中、标准默认小，每次切尺寸重设默认，允许手选。三主题与原UI组件继续复用。
- 手机的所选比例和临时窗口适配分开保存，浏览器缩放按DPR和visualViewport补偿，防止反复缩小累积。视口真的不足时允许暂时缩小，空间恢复后恢复所选尺寸。
- 不实现旧存档迁移，使用新卡和新聊天。

## 数据与写入归属

统一根为原生多楼层MVU的 `stat_data.shenghao`，没有新增另一套数据库。

| 字段 | 写入方 | 消费方 |
| --- | --- | --- |
| user.age/appearance/body | 开局初始化 | 我的、开局预览、共享上下文 |
| characters[id].personalityTags/appearance/body/heightCm/weightKg/bustCm/waistCm/hipCm/shoeSizeEu | 初始简易生成或首次正式收录；随后受保护 | 基础资料、现场、建档约束、在场上下文 |
| knownFacts/knownFactsEvidence | 初始化备注；后续模型须逐字正文依据 | 建档、在场上下文 |
| profileFixed | 玩家建档事务，九类或null | 四组详情；在场未锁定上下文 |
| profileLocked | 玩家锁定事务 | 详情状态、上下文筛选 |
| currentClothes/Pose/Action/Expression/Mood/Condition/Items | 原生MVU根据正文提案 | 现场展开区、在场上下文 |
| prefs.fontSize/phoneSize | 玩家设置，本地聊天偏好 | 手机样式与几何尺寸 |

建档与锁定复用现有玩家操作日志，随当前楼层/候选回复重放，幂等，写后重读。无新增远程服务。generateRaw沿用项目已验收接口及 `.cache/helper/@types/function/generate.d.ts` 相邻声明；不假设其自动写聊天。MVU和Zod仍为卡内加载器+固定CDN运行依赖。
