## 三、期间抓到的 P0：印记落库 ZodError（已修）

**现象**：用例 3 首次运行时保存失败，toast 原文「操作未能完成（ZodError），请稍后重试。」，`operationHistory` 为空。

**归因（F9 · 变量/结构层被宿主规则拒收）**，证据链：
1. 用真实种子存档复现（`.work/tools/repro-zod-imprint2.mjs`）：种子态校验 **OK**，模拟 save 一次后校验 **FAIL**；
2. issues 原文：`shenghao.characters.char_a.imprints.items.<其余 18 个部位> | Invalid input: expected object, received undefined`；
3. 根因：`schema.js` 写的是 `items: z.record(imprintPlacementEnum, imprintEntry)`。**zod 4 把枚举键当成「必须齐备」**，所以只刻 1 处时，其余 18 处被判成缺失 → 整卡校验失败 → 引擎写入被整体拒绝。
4. 影响面：凡「只刻 1–18 处」的存档都会在写入/读档校验阶段失败，属 P0 而非外观问题。

**修复**（最小改动，1 行）：`z.record(imprintPlacementEnum, imprintEntry)` → `z.partialRecord(imprintPlacementEnum, imprintEntry)`，键名仍受枚举约束（非法部位键照样被拒）。

**回归单测**：`tests/rc46-imprints-schema.test.mjs`（3 条）
- 单处落库后整卡 + root 校验通过；
- 19 处满刻校验通过；
- 伪造非法部位键仍被拒。

**复测**：改完后重跑用例 3 → PASS；全套单测 **467 / 467**；`BUILD_OK` / `CHECK_OK`。

## 七、第二轮：回抄后又查出两处真实缺陷（已修，2026-11-22 01:3x）

起因：YG 追问「确定都做完了吗」，我按清单逐项回查，发现交付报告没覆盖**输入路径**，于是补查打字链路，查出两处：

### P1·T-07 打字实时预览整条死掉

- **现象**：在印记工坊输入框里打字，舞台图案不重绘。
- **证据**：`app.js` 的 input 处理器取的是 `document.querySelector('.ws-stage svg')`；而 DOM 里根本没有 `.ws-stage` 这个类（卡片上是 `.ws-stage-card` / `#imprintStageSvg`），选择器恒为 null。
- **原型对照**：proto-imprint:771-775 的输入监听调用 `patchStage()`，打字即重绘。
- **修法**：改用原型 id `#imprintStageSvg`，并同步更新 `#stageRightCap`；截断时回写输入框（原型同款）。
- **实机验证**：`.work/tools/diag-workshop-typing.mjs` → 舞台 innerHTML 由 777 → 1596 字节、正文含「陆氏私有」、副标题「魅魔心翼（纯纹样）」→「魅魔心翼 · 弧绕外缘」。

### P1·T-08 项圈输入不重绘舞台 + 两个字数计数都不动

- **现象**：项圈刻字打字，舞台不变、计数一直是 0。
- **根因**：①项圈输入分支只改计数、没有重绘 `#chokerStageSvg`；②两个分支都用 `t.parentElement.querySelector('.ws-count')` 取计数节点，而 `.ws-count` 在 `.ws-group-hd` 里、不在输入框父级（`.ws-input-row`）里 → 恒为 null。
- **修法**：改用原型 id `#wsTextCount` / `#insCount`；项圈补舞台重绘与副标题（原型 proto-choker:537-541 同款）。
- **实机验证**：`0/16 字 → 4/16 字`、`0/12 字 → 7/12 字`，两个舞台都重绘且渲染出刻字。

**复测**：工坊 3 条用例重跑 **3/3 PASS**，`apiCalls: 0`；单测 **467 / 467**；`BUILD_OK` / `CHECK_OK`。
