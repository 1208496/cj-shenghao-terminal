## 第 3 轮 · CUSTOM 方向 + 新人物年龄自洽

驱动 `.work/live-rc58-custom.mjs`；证据 `.work/live-rc58/live-custom-result.json`。
愿望：「让隔壁搬来一位高二的女学生，今晚来我家借点东西顺便认识一下」。

**这一轮表面上什么都没落库**（`world.time` 还是 10:00、没有新人物、`audit` 为 null）。查下去发现是模型自己的伤：

```
..."path":"/shenghao/characters/char_a/currentThought","value":"..."},{"op":"op":"replace","path":"/shenghao/characters/char_b/personalityTags",...
```

`{"op":"op":"replace"` —— 多了一层 `"op":`，整块 `<JSONPatch>` 不是合法 JSON，MVU 直接拒收，于是这一轮的所有补丁（含时间、两人档案、新人物 add）一起蒸发。**不是卡的问题，也不是 rc.58 引入的问题**，是模型输出质量（长补丁里手滑）。

把这一处语法修好后，**用模型原样的 patch 回放**（`.work/repro-rc58-round3.mjs`）：

| 检查 | 结果 |
|---|---|
| 补丁是否合法 | 修 1 处语法后 41 个 op 全部解析 |
| 命令被拦 | 0 条（`dropped=[]`） |
| 新人物落库 | ✅ `char_lin_zhixia`（林知夏，云澜一中高二学生） |
| 新人物年龄 | 模型写 **17** → 脚本收敛 **18**（不出现 25，也不出现未成年） |
| 在场名单 | ✅ 含新人物 |
| 世界时间 | ✅ 20:18 落地 |
| 结算 | ✅ 无 diagnostics |

结论：A 批的新人物年龄收敛在真实模型输出上成立；第 3 轮的「没落库」是模型 JSON 手滑造成的假阴性。

**值得你知道的一个既有特性**（非本批引入）：这类补丁只要有一处 JSON 语法错，整块被弃，整轮更新全丢。要不要给「坏 JSON 尽量救」加兜底，是个独立议题。
