## A. 宿主与坐标系（核心，未解）

### A-1 `getBoundingClientRect()` 谎报真实渲染尺寸

- **现象**：DOM 报告手机 `365×730`，屏幕上实际只画出约 `125×573`。
- **证据**：给 `#phone` 套 2px 纯品红描边后全屏截图，像素扫描得到标记框 `(1184,68)→(1308,640)` = **125×573 px**；同一时刻 `rect` 报 `365×730`，`iframe.getBoundingClientRect()` 也是 `365×730`。
- **根因判断**：宿主在 iframe 内容上叠加了额外缩放（约 0.34×），而缩放**不体现在 `getBoundingClientRect()` 里**。
- **影响**：**所有「拿 DOM 矩形算截图坐标」的方案在这张卡里必偏**。这不是公式问题，是输入错了。
- **建议**：任何走 CDP 的方案，必须先做「真实缩放测量」（见 A-3），禁止直接信 DOM 尺寸。
- **状态**：未解（阻塞 CDP 路线）

### A-2 CDP `clip` 的单位与缩放语义需要实测，不能照文档猜

- **现象**：`clip` 传 100 CSS px，输出 125 px；同一轴传 365 输出 456；再乘 1.25 后输出 570。
- **证据**：三轮实测输出尺寸：`100→125`、`365→456`、`456→570`；`devicePixelRatio=1.5625`，而实测系数是 **1.25**。
- **根因判断**：`clip` 以 **CSS px** 为单位，输出自动乘一个系数 k（本机 k=1.25，不等于 dpr 1.5625）；`clip.scale` 的实际语义与预期不一致。
- **影响**：我按「设备像素」传 clip，位置整体偏移约 1/1.25。
- **建议**：把 k 做成**运行时探针测量**（100 CSS 探针 → 输出宽/100），不要硬编码，也不要等同于 dpr。
- **状态**：已测得 k，但未与 A-1 叠加验证

### A-3 缺「真实缩放」测量件

- **现象**：想当然用 `dpr` 或 `iframeRect/innerWidth` 推缩放，两个都不对。
- **证据**：`iframeRect.width / clientWidth = 1`，但真实渲染是 0.34×（A-1）。
- **建议**：做一个 `measureTrueScale()`：在目标文档里插已知尺寸探针 → 截图 → 用像素量 → 得到真实系数；**这是唯一可信来源**。
- **状态**：思路已定，未实现

### A-4 停靠态 iframe 矩形超出视口

- **现象**：`displayDock:'bottom'` 时 iframe rect 高度变成 `1464 / 1588 / 825`，随时序变化。
- **影响**：基于 rect 的裁切完全不可用；只能依赖 `captureBeyondViewport` + 真实缩放换算。
- **状态**：未解

## B. ego 能力边界（已探明）

| 能力 | 结论 | 证据 |
|---|---|---|
| `page.setViewportSize` | **不存在** | `page.setViewportSize is not a function` |
| `page.frameLocator` / `locator` / `context` / `emulateMedia` | **不存在** | 同上，逐个报 not a function |
| `page.cdp()` / `task.cdp()` | **存在** | `Page.getLayoutMetrics` / `Emulation.setDeviceMetricsOverride` 往返成功 |
| `page.screenshot({clip, scale, fullPage})` | 存在，但 `fullPage:true` **无效** | 输出尺寸恒等于视口 |
| `page` 其它方法 | `click / fill / hover / press / keyboard / mouse / dragAndDrop / snapshot / waitForSelector …` | `Object.getPrototypeOf(page)` 实测 |
| `Emulation.setDeviceMetricsOverride` | 生效但探针判定 ok:false（判定逻辑问题） | 观测到 `innerWidth 1440 / dpr 1.0` |
