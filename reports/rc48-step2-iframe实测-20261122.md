## 1. 结论：真实缩放是 **0.82**，不是 0.34；而且它是均匀的

两档视口各测一次，同一套角标法：

| | pass 1（默认视口） | pass 2（扩高视口） |
|---|---|---|
| 顶层视口 CSS | 1638 × 802 | 1120 × 1760 |
| PNG | 2560 × 1253 | 2188 × 3438 |
| 栅格系数 `rasterK` | **1.5629** | **1.9536** |
| 顶层 iframe 元素 `sx / sy` | **1.5636 / 1.5620** | **1.9512 / 1.9512** |
| iframe 内 `.ws-topbar` `sx / sy` | **1.2784 / 1.2353** | **1.5997 / 1.5882** |
| 预期内层系数（`rasterK × 0.82`） | 1.2816 | 1.6019 |
| 手机 iframe：元素宽 ÷ 内容视口宽 | 299.30 / 365 = **0.8200** | 同 |

**读法**：
- 顶层元素 `sx ≈ sy ≈ rasterK` → 顶层没有被任何宿主缩放；
- iframe 内的 `sx` 恰好等于 `rasterK × 0.82`，误差 0.3%（pass1）/ 0.1%（pass2）；
- 两档视口下这个 0.82 不变 → 它是**结构性缩放**（宿主把 365 宽的 iframe 显示成 299.3），不是栅格误差；
- `sy` 比 `sx` 低 3.6% / 0.8%，来源是 `.ws-topbar` 只有 34 CSS 高，±1 像素舍入就占 2.9% —— 小目标上的固有误差，不是非等比。

**「0.34×」彻底结案**：那是手机右边和下边被视口切掉造成的读数。
