## 四、实机踩到的坑（已修）

1. **导入版轮盘打开是空白暗罩（YG 报「卡死」）**：旧卡的 READY→INIT 握手没走通，盘面没建出来，只留一层锁滚动、带 × 的暗罩，观感等同卡死。
   - 修复：子端 `WHEEL_OPEN` 也能建盘；READY 未被接住时每 1.2 s 重发、最多 4 次；父端每次 READY 都重发 INIT。
   - 复测：同环境重新注入新 runtime，READY→INIT 一次成功（`wheelDebug()` 显示 `ready:true, pending:false`，节点 244）。
2. **全屏层 GPU 风险**：去掉 `backdrop-filter: blur(4px)`（rc.34 的 `PageUnresponsive` 同源），改纯径向渐层暗罩 + `contain: layout paint`。

## 五、零 API 测试通道（照 4N 的 `AGY_PLAN_TEST_NOAPI.md` 落地）

- `scripts/test-noapi-seed.mjs`：按 5 套预置（`empty_bag / three_cards / wish_unlocked / high_wealth / max_pity`）生成**合法 Zod 状态**，写进 8001 的独立测试聊天 `__NOAPI_TEST_<preset>.jsonl`（1 楼、`is_user:true` 的 `variables[0].stat_data.shenghao`）；每次强制换 `meta.initKey`，自动作废旧 localStorage 操作日志；带备份 manifest 与 `--restore` 清场。
- `scripts/test-noapi-run.mjs`：拉起 ego space → 开 8001（**不连 API**）→ 选卡 → 切预置聊天 → 断言小手机自己出现（`display!==none` 且 `initKey` 命中、`#wizard` 不存在）→ 五页 tab 顺序与各页结构 → 全屏轮盘握手（`#wfSvg .ring` 出现）→ 几何量测（`.wf-side` 不越界、三盘按钮=3、`__CJ_WHEEL_ERR__` 为空）→ 零 API 抽一次并等确定性落定（`#wfResult.on` + 不 spinning + revision 前进）→ 刷新后重新选卡进聊天验状态仍在 → `fetch/XHR` 哨兵零违规断言。截图落 `reports/noapi-test-shots/`。
- **实跑结果**：5/5 预置全部 `status: PASS`、`apiCalls: 0`（`empty_bag / three_cards / wish_unlocked / high_wealth / max_pity`）。
- 与 4N 方案的两处偏差（已实测确认必须改）：
  1. **浏览器驱动用 ego 运行时**（项目里没有 playwright，也不新装包）；因此网络层用「`fetch`/`XHR` 审计哨兵 + 永不触发生成」替代 `page.route` 拦截，最终断言 `__NOAPI_VIOLATIONS__` 为空。
  2. **刷新回读要先重新选卡进聊天**：8001 的 `auto_load_chat=false`，刷新后必然回到欢迎页，直接断言 `revision` 会永远是 0。
- 落地时踩到的坑：ego 运行时里 `process.execPath` 是 `ego.exe`，`execFileSync(process.execPath, …)` 会把 seed 脚本当应用参数、静默不执行；已改成「execPath 不是 node 就用 PATH 里的 `node`」，并加 `SEED_NOT_WRITTEN` 新鲜度守卫，防止拿上一次的预置冒充本轮结果。
