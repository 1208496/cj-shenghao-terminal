在 `dist/<版本>/神豪终端.json` 获取整卡。导入内嵌世界书，启用角色正则和默认三条助手脚本，在第一条正文填写起点后开始新聊天。rc.9 每位正式成年女性的初始奖池为零；实际有效消费按受益分摊1:1入池，重要互动沿用评分奖金表。当前好感≥90且池大于零时可反复手动领取全部，每次按提现前现金等级锁定倍率；现金到账后等级重新计算。

现金低于1000万元为见习十倍，1000万至不足1亿元为初级八倍，1亿至不足10亿元为中级五倍，10亿至不足100亿元为高级三倍，100亿元及以上为满级一倍；消费也可使等级下降。人物详情可查逐笔消费、退款和提现。已领消费退款按原提款倍率形成该人物后续抵扣，不改历史提款、不立即扣现金。

玩家开局颜值1–100，默认60。前期有效正向互动按颜值修正基础增量；女性事件前好感达到70后不再修正。女性颜值仅作为设定展示。正式相识自动简易建档，九类完整档案由玩家手动生成。rc.9需要新聊天，旧rc.8成品保留供回退，不对未发行测试存档增设迁移层。

手机主入口为「此刻」「她们」「我的」。点击「此刻」的日期可打开月历，登记或取消约定；日期与时间随故事推进，查看日历不会自动赴约。设置提供检测更新、三套主题、精巧/标准尺寸及隐藏人物恢复。头像与立绘独立上传；本地图片存储于当前浏览器，不能随聊天跨设备同步。

当前修正版类型为 **mvu_zod**，必须使用随卡的原生 MVU 与 Zod 结构注册。权威存档为原生消息楼层变量 `stat_data.shenghao`，手机读取同一份人物、现场、时间、日历与财务。模型输出 `<UpdateVariable><JSONPatch>`，程序在 MVU 生命周期内核对经济事实并计算金额。更新模式、额外解析接口和重试均由 MVU 自带面板管理；手机不提供重复的剧情同步设置，也不另发一套整理请求。

需要酒馆助手 4.12 的 Zod 4 能力。随卡四条脚本：Zod 注册、原生 MVU 国内加载器、默认关闭的全球备用加载器、结算与手机。国内与全球线路互斥，通常只启用默认三条。固定提交的远程依赖需要联网，来源与许可见 [第三方说明](docs/third-party.md)。不要同时启用旧卡的现金或返现脚本。

alpha.1、alpha.2、rc.1 使用过自定义事件方案，不符合本次原生 MVU 要求；其“通过”结论不沿用。请使用修正版新聊天，不把旧存档当作可直接兼容的数据。

开发环境为 Node.js 20+：

```sh
npm ci
npm run verify
```

`npm run build` 从维护源码生成整卡、世界书、开局页、手机页、运行脚本与 SHA-256 清单。`npm run preview` 仅用于本地开发预览。`SHEJI` 为原始设计依据，`src` 为源码，`dist` 为构建输出，`tests` 为确定性检查。禁止从产物反向覆盖源码。

正文底部默认提供可展开的「本轮变量更新」，以代码文本展示原生更新数据，并跟随终端主题。保留的「变量更新 · 优先隐藏」正则默认关闭，启用后优先隐藏，无需逐个关闭折叠框规则。显示规则不改原始消息，不影响MVU解析。

当前更新采用“固定加载器→Supabase提交指针→jsDelivr不可变提交本体”，参考用户提供的《酒馆脚本热更新 (1).md》。先核对CDN内容，最后切指针；玩家下次打开自动取发布版本。世界书、开场白、正则仍需整卡导入。实现与验证范围见热更新说明及专项验收。updates/latest.json只保留历史rc.5记录，新方案不读取它。

具体通过项、未通过项及版本组合见 `evidence` 中的验收记录。自动化通过不等于真实模型总能理解正确；歧义金额、不完整档案或缺乏事实证据时拒绝相应候选并提示重试；合规退款按当前追回规则结算。
