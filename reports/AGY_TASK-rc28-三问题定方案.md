## 二、三项问题（现象 · 证据 · 定位）

### 问题 1 · 界面操作写在“最后一条消息”的变量里，回退楼层会静默撤销

**现象**：提现 150.76 万成功后 `/del 1` 删掉最后一条 AI 正文，现金从 ¥2,397,600 立刻回到 ¥890,000，奖池/提现记录一起消失，界面无任何提示。建档（30–50 秒生成）同样会被这条路径吃掉。

**实机证据**：`mutateState` 里 `const exact=messageList().at(-1)` + `replaceMvuData(vars,{type:'message',message_id:exact.message_id})`；删楼/换 swipe 就是换了一份楼层变量快照。

**影响**：玩家「先提现、再手滑删楼或换 swipe」= 钱凭空消失；不可逆感强。

**要你定的**：这类“不可逆落账”应该放在哪一层（聊天级变量 / 楼层外存储 / 追加式账本），以及回退时如何给玩家明确提示或禁止回退。注意不能破坏现有的 `/swipe` 分支一致性与 `sourceAnchor` 回滚语义。

### 问题 2 · 「公司账户流水」绕开 `user.cashCents` 硬约束

**现象**：玩家现金 100 万，指示“今天签、三百万下午到账”，模型在正文写成“动用晟世资本公司账户的对公流水”，个人 `cashCents` 一分不扣，也没有 `CASH_TRANSACTION` 记录。模型思考块里明写了这条规避理由（“个人现金只有100万，但动用公司账户，所以个人 cashCents 不动”）。

**影响**：`terminal-economy` 的「OUT 不得超过 `user.cashCents`」在“公司/家族账户”口实下形同虚设 = 一条无限资金通道。

**要你定的**：两条路线二选一或组合——
- (a) 把“公司/家族资金”纳入体系（可设定额度、计入累计支出与账本，或作为资产/信用额度）；
- (b) 提示词与结算双层收紧：正文允许口述公司账户，但**任何对外支付事实必须落到个人资金或明确的融资/借款流程**，否则不提交交易。
给出具体落点（世界书条目 / 协议 / 结算校验）与最小改动面。

### 问题 3 · 建档失败或超时缺少用户可见反馈

**现象**：`src/ui/app.js` 建档分支是 `try { … } finally { … }`，**没有 catch**：成功 `notify('九大档案已保存')`，失败时按钮恢复原样、无 toast、无错误。建档本身 30–50 秒，期间只有按钮文字变「正在建档…」，无进度、无取消。

**已存在的错误码**：`errorText` 里已有 `PROFILE_FACT_CONFLICT` / `PROFILE_ALREADY_BUILT` / `MODEL_TIMEOUT` 等映射，说明设计上本来要给提示，但这条路径没接上。

**要你定的**：失败提示接在哪（`catch` + `notify(errorText(e))`？还是统一错误面板？），是否加进度/取消，以及超时时长与 `generationWithTimeout` 的关系。
